# Данные Watersheds

[← К README](../README.md)

Растровые наборы не включены в репозиторий. Каталог описывает подготовленные данные восстановленного приложения; скрипта автоматической загрузки полного комплекта нет. Имена продуктов не заменяют сведения о происхождении и условиях использования конкретных файлов. Для собственной установки нужны локальные, подготовленные и согласованные растры.

## Какие данные нужны

Для выделения водосбора используется пара направлений D8 и накопления стока `FlowDir` + `FlowAcc`. Их CRS, размеры и привязка ячеек должны совпадать. Для полного ответа приложения также нужны общие тематические слои: высоты, уклоны, климат и земной покров. Почвенный анализ и тематические карты умеют возвращать отдельное состояние недоступности; отсутствие обязательного растра статистики может прервать запрос целиком.

Гидрологические пары должны быть одноканальными, иметь североориентированную сетку в метрической проекции и целочисленные коды D8. Статистика высот, уклонов, климата и земного покрова не перепроецирует бассейн автоматически: эти тематические растры должны использовать ту же CRS, что и гидрологическая пара. В текущем комплекте это `EPSG:3395`. Почвенный анализ и подготовка геометрий слоёв поддерживают преобразование CRS отдельно.

Один растр высот или только направления стока не делают модель доступной. Все пути определены в [config.py](../config.py).

```text
data/
├── dem/                 # FlowDir + FlowAcc, исходные пары или COG
│   └── cog/<model>/zstd/
├── heights/             # GMTED2010_30sec_Clip_Project_Fill.tif
├── slopes/              # GMTED2010_30sec_Clip_Project_Fill_Slope.tif
├── climate/             # 12 температурных + 12 осадочных растров
├── landcover/           # GLOBCOVER_Clip_Project.tif + словарь классов
└── soil/                # soil_map_M2_5.tif + словарь классов
```

Тематические COG размещаются в подкаталоге `cog/zstd` соответствующей папки, с исходным именем файла и соседним манифестом `*.tif.cog.json`.

Это примерные прямоугольники, внутри которых есть NoData. Обзорный контур строится по пересечению масок `FlowDir` и `FlowAcc`, обобщается и может пропускать мелкие пробелы. Весь расчётный водосбор должен помещаться в валидных данных.

### Как выбираются файлы

Приоритет гидрологических пар: полная локальная COG-пара в `data/dem/cog/<идентификатор в нижнем регистре>/zstd`, затем оригиналы в `data/dem`, затем внешний каталог `WATERSHED_DEM_DIR`. Если полной пары в одной папке нет, оригиналы ищутся отдельно в двух последних папках с предпочтением скачанных файлов. Один COG не смешивается с оригинальной второй половиной пары. Совместимость выбранных сеток проверяется перед расчётом.

По умолчанию внешний каталог — `Yandex.Disk/watershed/Data` в домашней папке пользователя. Его можно заменить перед запуском API:

```powershell
$env:WATERSHED_DEM_DIR = 'D:\Hydrology\Data'
.\start-backend.ps1
```

Тематические растры используют собственные константы. COG выбирается при наличии успешного манифеста, подходящих путей и сигнатур файлов; иначе выбирается путь оригинала. Температуры и осадки переключаются независимо, но только полными сериями по 12 месяцев. После изменения данных или путей перезапустите backend. Облачные заглушки автоматически не скачиваются.

## Общие слои анализа

Выбранная ЦМР определяет границу водосбора. Остальные показатели вычисляются по единым для всех моделей растрам:

| Показатель | Исходный файл / шаблон | Константа |
|---|---|---|
| Высоты | `data/heights/GMTED2010_30sec_Clip_Project_Fill.tif` | `ELEVATION_RASTER` |
| Уклоны | `data/slopes/GMTED2010_30sec_Clip_Project_Fill_Slope.tif` | `SLOPE_RASTER` |
| Температура | `data/climate/c1_30s_tavg_01_Clip_Project.tif` … `12` | `CLIMATE_TEMPERATURE_TEMPLATE` |
| Осадки | `data/climate/c1_30s_prec_01_Clip_Project.tif` … `12` | `CLIMATE_RAINFALL_TEMPLATE` |
| Земной покров | `data/landcover/GLOBCOVER_Clip_Project.tif` | `LANDCOVER_RASTER` |
| Почвы | `data/soil/soil_map_M2_5.tif` | `SOIL_RASTER` |

Высоты и уклоны подготовлены из GMTED2010 30″, шаг сетки около 1498 м. Почвы имеют шаг 250 м и NoData `65536`. Покров — около 499,266 м, NoData `255`; дополнительный код отсутствия данных `230` указан в словаре. Это размеры ячеек в проекции. Подписи классов находятся в [soil_categories.py](../data/soil/soil_categories.py) и [landcover_categories.py](../data/landcover/landcover_categories.py).

Климатические ряды содержат 12 значений в порядке январь–декабрь. Детализация модели границы не изменяет разрешение общих слоёв. Почвенные категории описывают состав карты; по ним приложение не рассчитывает водопроницаемость или параметры стока.

## Подготовка накопления стока

Для имеющихся направлений MERIT и ALOS накопление можно подготовить отдельно:

```powershell
.\venv\Scripts\python.exe scripts\prepare_flow_accumulation.py --source ALOS_local
.\venv\Scripts\python.exe scripts\prepare_flow_accumulation.py --source MERIT_3sec
```

Скрипт использует направления из настроенного каталога и записывает накопления в `data/dem`. Сетка и маски сохраняются. Выход — сжатый BigTIFF `uint32`, NoData `4294967295`; значение равно числу вышележащих ячеек **без текущей ячейки**, как в ESRI Flow Accumulation.

В подключённых наборах используется D8 ESRI: `1=E`, `2=SE`, `4=S`, `8=SW`, `16=W`, `32=NW`, `64=N`, `128=NE`. Неизвестные коды и циклы приводят к ошибке. Перед публикацией перечитывается весь выходной растр и проверяются счётчики и маски; рядом сохраняется `*.tif.preparation.json`. Существующие результаты не перезаписываются.

Этот модуль рассчитан на Windows и 64-битный компилятор .NET Framework `csc.exe` из `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319`. C#-ядро собирается автоматически. Для `N` ячеек временные файлы занимают `6N` байт; проверяется запас `10N + 256 МиБ` на диске назначения. Для восстановленных файлов это около 6,9 ГиБ у ALOS и 13,1 ГиБ у MERIT. История исходной обработки этих локальных наборов неполна; проверка согласованности D8 не заменяет документацию поставщика.

## COG и проверка сохранности значений

Cloud Optimized GeoTIFF хранит тайлы и обзорные уровни внутри одного файла. В проекте используются ZSTD 9, блоки 512 × 512 и внутренние пирамиды NEAREST. Конвертер не меняет CRS, сетку или тип данных и не удаляет оригинал.

Пример для существующего растра и ещё не занятого выходного пути:

```powershell
.\venv\Scripts\python.exe scripts\prepare_cog.py --input 'D:/Hydrology/new_FlowAcc.tif' --output 'data/dem/cog/new-model/zstd/new_FlowAcc.tif' --compression ZSTD
```

Публикации предшествует полное сравнение исходных пикселей и масок. Манифест `*.tif.cog.json` содержит SHA-256 данных, размеры, параметры и результаты проверки. Хеши относятся к значениям в порядке обхода блоков, а не к сжатым байтам TIFF. Перед запуском оценивается запас диска; внешняя локальная `.msk` переносится внутрь COG. Облачная или неподдерживаемая маска вызывает ошибку. Существующие выходные файлы и манифесты не перезаписываются.

Для фиксированного комплекта тематических оригиналов доступны обёртки:

```powershell
# Аудит всех почвенных, земельных и климатических оригиналов.
.\venv\Scripts\python.exe scripts\prepare_thematic_cog.py

# Полный исходный комплект должен быть доступен для аудита обеих команд.
.\venv\Scripts\python.exe scripts\prepare_thematic_cog.py --convert --groups landcover precipitation temperature
.\venv\Scripts\python.exe scripts\prepare_thematic_cog.py --convert --groups soil --staged-groups soil --report artifacts/thematic-cog/soil-conversion.json

# Высоты и уклоны.
.\venv\Scripts\python.exe scripts\prepare_terrain_cog.py --convert
```

Для отдельных файлов предпочтителен универсальный `prepare_cog.py`. Параметр `--staged-groups soil` сначала создаёт сжатую временную основу и повторно оценивает запас диска перед созданием пирамид. Проверки `--verify-existing` у тематических обёрток также требуют оригиналов.

В восстановленной установке COG проверены по всем исходным пикселям и маскам, а затем по результатам расчётов и слоям карты. Размеры рабочих копий: пары девяти моделей — около 3,40 ГБ; почвы, покров и 24 климатических растра — 745,67 МБ; высоты и уклоны — 203,17 МБ. Это размеры конкретного комплекта, не оценка для любых данных. Исходные TIFF той установки удалены после отдельной проверки по запросу владельца; конвертер сам их не удаляет.

### Перенос данных на другую машину

У гидрологических пар пути COG заданы каталогом, совместимость сетки проверяется при открытии. Для тематических слоёв, высот и уклонов автоматический выбор COG дополнительно проверяет манифесты с **абсолютными путями** и сигнатурами исходных файлов.

Поэтому перенос папки COG и старых манифестов в другой каталог может привести к возврату на пути отсутствующих оригиналов. Предусмотренный путь подготовки новой установки — разместить оригинальные TIFF в ожидаемых папках и создать новые COG со свежими манифестами. Ручная замена путей в отчёте не выполняет проверку данных. Если доступна только перенесённая COG-копия, её подключение и проверку нужно настроить отдельно; автоматической миграции манифестов сейчас нет.

## Что означают результаты

- **Полнота водосбора.** Расчёт расширяет локальное окно, но ограничен 16 млн ячеек. Касание края растра или соседство с NoData трактуется как неполное покрытие. Проверка может отклонять прибрежные бассейны, где NoData обозначает море.
- **Площадь.** Вычисляется по геометрии в проекции расчёта. Для Меркатора это не геодезическая площадь; искажение зависит от широты.
- **Доли классов.** Почвенная статистика учитывает центры ячеек внутри бассейна; проценты относятся к валидным пикселям. NoData исключается, покрытие данными показывается отдельно. Округлённые доли могут не дать ровно 100%.
- **Статистика и карта.** Геометрия слоя обрезает пересечённые крайние ячейки, поэтому краевой класс может присутствовать на карте без доли в статистике. Крупные слои обобщаются и при необходимости ещё укрупняются; мелкие классы могут исчезнуть. Для почвенного анализа и подготовки тематических слоёв исходное окно ограничено 100 млн ячеек.
- **Высоты и уклоны.** Цветовая шкала подбирается отдельно для каждого бассейна, до 24 интервалов. Одинаковый цвет разных бассейнов может означать разные значения. Уклоны вне диапазона 0–90° исключаются из слоя; отрицательные высоты допустимы.
- **Подсказки.** Для высоты и уклона читается исходная ячейка 1 × 1; значение может отличаться от обзорного цвета. Названия почв и покрова берутся из показанной геометрии. NoData и отверстия прозрачны.

Покрытия ЦМР кэшируются в `data/dem/coverage_cache`. Кэш зависит от путей, размеров, времени изменения данных и масок, а также версии алгоритма. При построении покрытий, анализе и отображении исходные растры не изменяются.
